# ADR-0023 — Python 3.15

**Status:** substituída pela ADR-0034 · **Data:** 2026-10-11 · **Marco:** M0
**Altera:** CLAUDE.md, tabela de stack ("Python 3.13+ (3.14 se as dependências suportarem)")

## Contexto

O CLAUDE.md pede a versão mais nova que as dependências suportarem. O Python 3.15.0 saiu em 09/out/2026, dois dias antes desta decisão.

## Verificação (11/out/2026)

Ambiente de teste com Python 3.15.0 (gerenciado pelo `uv`) e as dependências previstas para a v0.1:

| Resultado | Pacotes |
|---|---|
| Instalam com wheel pronto | pydantic 2.14, fastapi 0.143, nats-py, jsonschema, orjson, pytest, pytest-asyncio, hypothesis, ruff 0.17, pyright 1.1.414, import-linter, datamodel-code-generator 0.83, httpx |
| Compilam a partir do código-fonte | `pyyaml` (sem a extensão C opcional, que só acelera a leitura; irrelevante para arquivos de configuração) e `httptools` (extra `uvicorn[standard]`) |

- **Ferramentas:** o `ruff` aceita `py315` e entende `lazy import`.
- **pyright:** entende a sintaxe nova, mas o stub de `frozendict` ainda recusa argumentos nomeados (`frozendict(a=1)`). Usar `frozendict({"a": 1})`.
- **Codegen:** o `datamodel-code-generator` ainda não aceita `--target-python-version 3.15`. Gerar com alvo `3.14`; o código gerado roda no 3.15.
- **Biblioteca padrão:** já traz `uuid.uuid7()` (3.14+) e `frozendict` (3.15), o que dispensa dependências para UUIDv7 e ajuda no estado imutável.

## Decisão

- Python **3.15**, fixado em `.python-version` e `requires-python = ">=3.15"`, gerenciado pelo `uv`.
- Plano de volta: se alguma dependência quebrar, trocar para 3.14 (já instalado pelo `uv`) e registrar nova ADR.

## Consequências

- Recursos novos disponíveis desde o início: `lazy import`, `frozendict`, `uuid7`.
- Algumas ferramentas ainda vão se ajustar ao 3.15 nas próximas semanas (alvo do codegen, stubs do pyright). Os contornos acima ficam documentados no código onde forem usados.
